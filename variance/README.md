## Recent Fixes (December 2025)

### 1. NULL `claim_amount` Handling

**Issue**: Claims with NULL `claim_amount` were defaulting to $0, causing incorrect $0 approvals when they should approve at `max_benefit`.

**Fix**: Modified `rule_evaluator.py` and `claim_repository.py` to:
- Return `None` instead of `0.0` when `claim_amount` is NULL
- Use `max_benefit` as cap when `claim_amount` is NULL
- Only approve $0 if `claim_amount` is explicitly 0 AND no `max_benefit` exists

**Impact**: Fixed 17 out of 30 claims that were incorrectly approving at $0.

### 2. Deterministic Rule Engine

**Status**: Implemented

Implemented phrase-based category detection to reduce LLM variability in line item classification. This provides consistent categorization of line items (rent, cleaning, repairs, etc.) independent of LLM interpretation.

**Impact**: Reduces variance from inconsistent LLM categorization.

### 3. LLM Result Caching

**Status**: Implemented

Caches LLM document analysis and line item extraction results. When rerunning claims with updated rules, the system reuses cached LLM results and only reapplies deterministic rules.

**Impact**: Significant cost savings (avoids redundant LLM calls) and faster reruns.

### 4. Concurrency Control

**Status**: Implemented

Added global semaphore for Gemini API calls to prevent rate limiting and improve stability.

**Impact**: Prevents API rate limiting, improves batch processing reliability.

## Root Cause Analysis

### Primary Issues Identified

1. **Document Availability**
   - Some claims lack invoice documents in Google Drive
   - System correctly denies when no documents available
   - **Status**: Not a system issue, data quality issue

2. **Utility Charges**
   - System was approving utility charges (water, gas, etc.)
   - **Fix**: Added utility charges to denied categories
   - **Status**: Fixed

3. **External Factors**
   - Some denials are due to external agreements (tenant paying PM directly)
   - **Status**: Cannot detect external factors programmatically

4. **Evidence Requirements**
   - Some approvals require more evidence than system can evaluate
   - **Status**: Ongoing - may require additional document analysis

## Ongoing Efforts to Mitigate Variance

### 1. Deterministic Rule Engine

**Status**: Implemented and continuously refined

Phrase-based category detection provides consistent categorization independent of LLM interpretation.

**Impact**: Reduces variance from inconsistent LLM categorization.

### 2. Cap Management

**Status**: Implemented

Improved cap calculation logic with clear reason tracking (claim_amount, max_benefit, invoice_total). System correctly handles NULL `claim_amount` cases.

**Impact**: Ensures caps are applied correctly and transparently.

### 3. Parallel Processing

**Status**: Implemented

Optimized Google Drive document processing with parallel downloads and batch metadata fetching. Global semaphore controls Gemini API concurrency.

**Impact**: Faster processing and better resource utilization.

### 4. Historical Analysis

**Status**: Ongoing

Tracking variance over time to identify patterns and systematic biases. Variance reports generated regularly.

**Impact**: Enables data-driven improvements to rules and prompts.
